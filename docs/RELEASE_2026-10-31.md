# 首个源码测试版验收

版本：`0.1.0-alpha.1`（Python 包版本 `0.1.0a1`）。日期：2026-10-31。目标为可安装、可试用、可报告问题的 Windows x64 / Python 3.12 源码测试版；不是稳定版或全自动漫画质量承诺。

## 此轮实际修改

- 修复不同文件夹的同 stem 图片、不同扩展名和大小写冲突导致的元数据、译图及归档覆盖。ZIP/EPUB 各输入独立提取，内部生成名也循环避让。只对歧义页保存临时副本，普通唯一文件名输入不复制。
- 队列从“一页一个等待任务”改为固定数量 worker。重试、取消、安全停止、异常恢复和连接清理有独立回归覆盖。
- 配置 Windows 应用身份 `Personal.MangaTranslator`、显示名和图标；仅正常启动注册当前用户的应用资产，工厂测试不写真实注册表。点击通知恢复窗口且保留最大化。失败记录警告并继续启动，不改通知权限或安全设置。
- 安装约束固定经过验证的直接/传递依赖，首发仅支持 Python 3.12 x64。只使用 PySide6-Essentials，不下载无用的 Addons。
- 干净安装暴露了构建临时目录及 Qt wheel 的长路径问题。安装脚本使用较短构建目录与 Windows 扩展路径，不要求用户修改全局长路径设置。
- 添加 MIT 许可、第三方与模型来源、快速入门、反馈模板、发布说明、Windows CI 和可复现白名单源码 ZIP。

## 功能与质量

保留之前的原图保护、样式/蒙版编辑、检查导航、缓存失效、人工译文交换和异常恢复验收。本轮新增同名输入、有限 worker、安装/发行边界与 Windows 身份的回归。

自制日文样本位于 `docs/samples/`，生成脚本 `scripts/qa_japanese_samples.py`；人物、气泡、线条与短句是原创验收夹具，不分发第三方漫画或字体文件。默认 RapidOCR 3.9.2 实测：

| 样本 | 观察 |
| --- | --- |
| horizontal.png | 两句横排日文完整识别，但人物线条被额外识别为 `4` 并标为待检查 |
| vertical.png | 文本拆为多个区域，出现漏字与误识别，未完整还原两句；必须人工校对 |
| textured.png | 两句横排与 `ドーン` 被完整识别；这不代表任意效果字都可靠 |

三张仅识别输出的像素都与原图一致。脚本的最佳字符串相似度仅用于诊断，不能称为字符准确率或代表性漫画评测。完整结果在本地忽略目录 `.artifacts/release-japanese-01/report.json`。

## 性能测量

独立 `scripts/benchmark_queue_workers.py` 对10,000个合成页面、并发2，前后各5轮：

| 指标，中位数 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 创建的 asyncio Task | 10,000 | 2 |
| Python 追踪峰值 | 14,460,269 bytes | 1,872,418 bytes |
| 调度耗时 | 1.632秒 | 1.022秒 |

全部10轮页面状态、尝试次数和结果路径 SHA256 一致。该基准开启 tracemalloc，排除 SQLite、图片、OCR 和网络；这只说明调度开销减少，不能推导全应用内存同比下降或整本翻译加速。原始结果在 `.artifacts/perf-queue-workers/`。

上轮重复样式重绘和进度刷新改善继续保留；其端到端仅识别耗时没有改善，见 [上一轮测量](PERFORMANCE_2026-10-28.md)。

## 发布验收边界

- 新虚拟环境必须来自源码 ZIP 的解压目录，从官方包索引安装，不复用正式 site-packages 或模型文件；先准备模型，再禁止网络验收本地流程。
- Windows CI 会从同一白名单源码包安装、运行完整测试与实际 OCR 冒烟，保留报告；只增加工作流文件不等于 CI 已通过，最终状态以 Actions 运行结果为准。
- 付费服务验收只发送自制短句和样本识别文字，不发送原图或私人漫画。密钥只在进程内使用，不进入报告、Git 或发行包。
- 源码 ZIP 附逐文件 SHA256 清单及包校验值，不包含 `.git`、`.venv`、运行数据、密钥、日志、模型、字体或本地验收产物。
- Git 历史与最终源码分别做脱敏密钥扫描；扫描通过不构成“绝无敏感内容”的保证，仍核对候选文件清单。
- 正常 Windows 进程中可通过系统 API 读回正确 AppUserModelID；真实通知横幅顶部显示还需按本机实际截图确认，不把 API 测试描述成系统截图验收。

安装日志、测试结果和 CI 链接会在最终发布时补入本记录；失败尝试与成功验收分开保留。
