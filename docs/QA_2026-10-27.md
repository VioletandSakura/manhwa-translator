# 2026-10-27 第一轮实际试用

## 验证方式

本机 Windows、Python 3.12.13、PySide6 6.11.1。打开了实际应用，并使用 Qt 自带的测试事件驱动真实窗口和控件。桌面操作连接在初始化时连续失败，因此本轮未能完成依赖系统鼠标工具的人工式逐项点击。

检查脚本 `scripts/qa_desktop.py` 使用两张自行绘制的英文对话气泡样本和独立运行目录。真实执行本地 RapidOCR、任务队列、OpenCV、Pillow、SQLite 和文件导出；原生系统文件选择窗口在脚本中被替代为固定的测试路径。

## 已验证

- 第一轮自动化测试为 173 项通过；增加启动器与真实服务兼容性修整后，最终为 177 项通过（最近运行耗时 10.04 秒）。
- 11 个界面页可以创建和显示，并保存截图供检查。
- 文件夹内两页按自然顺序导入，分别识别到 `HELLO FRIEND!`、`LET US GO HOME!`。
- 未调用翻译 API 的任务完成，两个输出图与各自原图的像素完全相同。
- 在队列选择第一页，可以通过按钮打开编辑器、选择检测框，填写“你好，朋友！”。
- “保存并重绘译图”实际写入元数据并生成中文图片，已查看生成图片。
- 重绘完成回调在界面线程执行，编辑器能直接刷新生成图片；澳门区域设置下数字保持阿拉伯数字。
- 通过真实界面按钮执行 TXT、JSON 和译图 ZIP 导出；ZIP 中有两个页面且 CRC 检查通过。
- 数据目录继续保留现有历史，默认新输出移至项目内 `outputs/`，没有修改旧输出目录的 Windows 访问权限。

相关本地证据由脚本保存在指定的 `.artifacts/` 子目录中。该目录不提交到 Git；可按 README 的命令重新生成。

## 本轮修复

默认路径、启动器与安装脚本的本机路径依赖；输出目录写入预检查；OCR-only 擦除原文；编辑器入口缺失；编辑保存没有收集输入框内容；文字编辑不能正确撤销；CBZ 选择过滤器遗漏；更改输入路径仍沿用旧选择；任务准备失败后按钮无法恢复；后台回调跨线程更新界面；澳门区域下数字显示为苏州码子。

## 启动窗口问题的后续修复

发现本机 uv 环境中的 `pythonw.exe` 与 `python.exe` 内容相同，均为控制台程序，因此关闭附带控制台会结束软件。新增 `.vbs` 无窗口入口和 `scripts/launch_gui.py`，检查真实 PE 类型，并在需要时使用本机 CPython 自带的 venv GUI 重定向程序；不重建依赖环境。

新增 3 项启动器回归测试通过。实际子进程验证 `GetConsoleWindow() == 0`，且发起启动的进程退出后，GUI 进程仍在运行。通过新入口启动实际应用后，软件窗口正常响应。启动错误写入 `logs/startup.log`。

参考同类上游缺陷：[uv #19226](https://github.com/astral-sh/uv/issues/19226)。

## 真实 DeepSeek 验证

用户授权后，从本地现有配置中读取密钥，只向 `https://api.deepseek.com` 发送验证和翻译请求。账号模型列表实际返回 `deepseek-flash` 和 `deepseek-v4-pro`，本次使用前者。

通过完整桌面流水线完成两张自制英文示例图的 OCR、付费翻译、擦字、中文渲染和导出，另发送三句自制日文对话。共 3 次真实生成请求，均 HTTP 200、正常结束；服务端报告输入 332 tokens、输出 55 tokens，总计 387 tokens。未推算金额，实际账单以服务商为准。

| 输入 | 真实返回 |
| --- | --- |
| `待って！その扉を開けないで！` | 等等！别打开那扇门！ |
| `HELLO FRIEND!` | 你好，朋友！ |
| `LET US GO HOME!` | 我们回家吧！ |

重复查询第一页文字命中本地缓存，没有增加生成请求。API 返回的两张译图均单独保存，并进行了视觉检查；报告、截图、JSON、TXT 和 ZIP 位于本机 `.artifacts/qa-live-deepseek/`，不提交到 Git。

正式应用的 DeepSeek 密钥已保存至当前 Windows 账号凭据管理器，模型更新为已验证的 `deepseek-flash`。默认模型名和普通翻译的非思考模式已调整；仅官方 DeepSeek 域名附加该模式参数，通用兼容接口不接收专属参数。

参数依据：[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。GitHub 仓库核对见 [远程状态](GITHUB_STATUS.md)。
